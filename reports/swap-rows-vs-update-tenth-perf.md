# Investigation: swapRows ~40x slower than updateEveryTenth

## Bottom Line
**Root Cause**: `swapRows` mutates the exact leaf paths (`data.<i>.id`) that the list component's auto-tracker registered as interest (via `key={item.id}`), so it wakes and re-renders/re-maps all 1000 rows; `updateEveryTenth` only mutates `label`, a field the list component never reads, so its dirty-path diff produces zero matches and the list component never re-renders at all.
**Fix Location**: `apps/perf/src/libraries/blac/FrameworkBenchmark.tsx:109-111` (list only tracks `item.id` via the `key` prop, not `item.label`); mechanism lives in `packages/dirtytalk-structural/src/container.ts:333-408` (`_refineAncestorMarks`) and `packages/dirtytalk-structural/src/tracker.ts:311-339` (leaf-path recording).
**Confidence**: Medium-High

## What's Happening
`updateEveryTenth` replaces 100 item objects in place (same id, new label) and finishes in <4ms because the parent list component's tracked interest set never intersects the dirty paths — it simply doesn't re-render. `swapRows` moves only 2 items but changes the `id` value observed at 2 array indices, which is exactly what the list component tracks for its React `key`, so it wakes, forcing a full re-render/re-map of all 1000 `<Row>` elements plus proxy-tracking and React reconciliation over the whole array — dominating the 150ms.

## Why It Happens
**Primary Cause**: `@dirtytalk/structural` treats arrays as atomic leaves (`isPlainPatchObject` in `diff.ts:10-14`/`container.ts:423-427`), but the recording proxy in `tracker.ts` still records fine-grained per-index leaf paths when a consumer's render iterates/reads into the array (`tracker.ts:146-157`, `293-339`). The list component's render does `state.data.map(item => <Row key={item.id} item={untracked(item)} />)` (`FrameworkBenchmark.tsx:109-111`); reading `item.id` for the key records leaf path `data.<i>.id` and (per the "drop parent on deeper read" rule, `tracker.ts:311-339`) never records `data.<i>.label`, since `item` itself is passed through `untracked()`/`raw()` (`tracker.ts:79-103`) before Row reads `.label` — that read is detached from the parent's tracker entirely.
**Trigger**: `container.ts:239-246` (`patch`) — `changedPathsFromPatch` marks `data` as an atomic-replaced ancestor, then `_refineAncestorMarks` (`container.ts:354-408`) walks the registered skeleton and, for each `data.<i>.id` leaf, does `Object.is(prev, next)` (`container.ts:401-404`) — a value-filtered, per-leaf comparison, not a move/LCS diff.
**Decision Point**: `container.ts:404` — for `updateEveryTenth`, `id` is unchanged at every index, so `_refineAncestorMarks` returns a dirty set that doesn't intersect the list's interest; `DirtyChannel.mark`/`flush` (`packages/dirtytalk-engine/src/dirty-channel.ts:128`, `intersects` check) skips the list consumer entirely — no re-render, no re-map, no proxy-tracking pass over 1000 items. For `swapRows`, `data.1.id` and `data.998.id` do change value, so they land in the dirty set, the list's interest intersects, and the list component re-renders — re-invoking `trackRender` (`tracker.ts:173-419`) over all 1000 items (fresh `Proxy` per item, `interner.intern()` per leaf, `WeakMap`/`Set` bookkeeping) and re-running `.map()`/React reconciliation for the whole list, not just the 2 moved rows.

## Evidence
- **Key File**: `apps/perf/src/libraries/blac/FrameworkBenchmark.tsx:31-38` vs `:58-66` — `updateEveryTenth` only ever writes `.label`; `swapRows` only ever changes which `id` sits at index 1/998 (identity swap), never touching `.label`.
- **Key File**: `packages/dirtytalk-structural/src/tracker.ts:311-339` — leaf-recording/"drop-parent" logic: only the deepest read (`item.id`) is retained as an interest path; `untracked(item)` (`tracker.ts:79-103`) means Row's `.label` read never reaches the parent's tracked set at all.
- **Key File**: `packages/dirtytalk-structural/src/container.ts:354-408` — `_refineAncestorMarks` is a single O(skeleton size) pass with a plain per-leaf `Object.is`/`equalsAt` comparison; there is **no** index-distance-sensitive, move-detection, or O(n²) code path found anywhere in `diff.ts`/`container.ts`/`tracker.ts` — cost is proportional to the number of registered leaf paths under the changed ancestor, not to "move distance."
- **Search Used**: `rg "isPlainPatchObject"` and reading `diff.ts:10-14` — confirms arrays are always atomic/leaf for patch diffing; no per-index array reconciliation algorithm exists in this codebase.
- **Search Used**: `rg "trackRender|select" packages/blac-react/src/useBloc.ts` — confirms both `Row` and the list component use default auto-tracking (`trackRender`), not `select`, so both are subject to the per-leaf path mechanism above.
- **Key File**: `packages/dirtytalk-engine/src/dirty-channel.ts:128` — `intersects(interest, dirty)` gate: consumers with no path overlap are never invoked, explaining why `Row` (interest = `selected` only) is unaffected by either operation, and why the list component is skipped entirely for `updateEveryTenth`.

No existing TODO/comment in the code explicitly names this swap-vs-update asymmetry; the closest acknowledgment is the tracker's own documentation of leaf-path/parent-drop semantics (`tracker.ts:126-157`) and the D2 item in `reports/perf-opportunities-blac.md:11` about the default proxy being "a fresh object every render by design."
