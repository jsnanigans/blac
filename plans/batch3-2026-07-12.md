# Plan: Batch 3 — DirtyChannel/PathInterner/deepMerge perf + watch() dispose churn

## Decision
**Approach**: Ship the four items that are perf-tier but already fully
designed and single-file/single-mechanism: `DirtyChannel` size<=1 flush
fast-path (+ `onError` doc), `PathInterner` ancestor-memo length-versioning
(+ dev-warn), `deepMerge` lazy-clone (execute the existing plan), and a new
`ON_DISPOSE` per-instance symbol so `watch()` stops filtering every app-wide
disposal. Ship `emit()`'s opt-in `skipEqualityCheck` only pending explicit
developer sign-off (flagged below, not silently decided). Drop the
`useStructural`/`useBloc` shared mount-gap helper and the ancestor-marks
path-trie from batch 3 entirely — verified below that neither earns its
risk.
**Why**: These four are the highest impact÷risk items left standing after
batch 2, each confined to one file/mechanism with an existing test file to
extend, matching batch 1/2's shape and size.
**Risk Level**: Medium (the DirtyChannel fast-path and `ON_DISPOSE` touch
shared re-entrant/lifecycle state; the other two are pure local rewrites
with reference-identity tests).

## Items Dropped From Consideration (with why)
- **`_refineAncestorMarks` path-trie**: the ancestor-memo fix below already
  makes `ancestorIds(id)` O(1) after first computation for a stable state
  shape (the common case) — a trie would only help the *first* computation
  per new path, which the report never measured as hot. No spike exists to
  justify the design/risk (`L` effort, trie node granularity undecided).
  Defer until a bench shows the memo fix insufficient.
- **`useStructural`/`useBloc` shared mount-gap helper**: checked both
  hooks — `useBloc.ts` is ~940 lines (select-mode, cross-bloc dep
  reconciliation, rebind-nonce lifecycle) vs. `react-hook.ts`'s ~65 lines;
  only the auto-track branch's 3-line "state advanced since render → force"
  check is textually identical. Both hooks already independently pin this
  invariant (`react-hook.test.ts:371` "T6", `useBloc.lifecycle-edge-cases.test.tsx:123`
  "R2") — there's no missing test coverage to add and no perf win. Forcing a
  shared helper would add cross-package indirection for 3 lines while the
  surrounding lifecycles diverge completely. Not doing this; revisit only if
  a third hook needs the same pattern (rule of three).

## 1. DirtyChannel `size<=1` flush fast-path
**File**: `packages/dirtytalk-engine/src/dirty-channel.ts`
- In `#flush()` (`:104` `const live = Array.from(this.#subscribers.values());`):
  when `this.#subscribers.size <= 1`, skip the array snapshot. Read the sole
  entry directly (`this.#subscribers.size === 1 ? this.#subscribers.values().next().value : undefined`),
  check `entry.alive`, run the existing interest/cb/error steps inline on
  that one entry, sole `try/catch` blocks unchanged. `size === 0` already
  short-circuits earlier via the `isEmpty(dirty)` check when there's nothing
  to mark, but a mark with zero subscribers still reaches here — treat as a
  no-op loop (nothing to iterate).
- Must preserve: (a) a subscriber that unsubscribes itself mid-callback ends
  cleanly (`entry.alive` becomes false but the callback already ran); (b) a
  callback that `subscribe()`s a NEW second entry mid-flush must NOT invoke
  that new entry this cycle (matches test 14's contract) — since the fast
  path never snapshots `this.#subscribers`, re-check `this.#subscribers.size`
  is irrelevant here (the loop body only ever touches the one captured
  `entry` reference, never re-reads the live Map), so this holds by
  construction.
- Doc-only, same file: add a JSDoc note on `StructuralContainerOptions.onError`
  (`container.ts`, not this file — see below) — actually this belongs to
  `container.ts`'s option, not `dirty-channel.ts`; add the note there instead
  (see step 1b).

**1b. `onError` doc note** — `packages/dirtytalk-structural/src/container.ts:57-61`
(`StructuralContainerOptions.onError`): extend the JSDoc to state explicitly
that omitting it means subscriber/interest-thunk errors are re-thrown
synchronously inside the scheduler's microtask/rAF callback (uncaught,
crashes that tick) — no behavior change, doc only. Test 24
(`dirty-channel.test.ts:419`) stays pinned as-is.

## 2. PathInterner ancestor-memo: length-versioned instead of full clear
**File**: `packages/dirtytalk-structural/src/path-interner.ts`
- Add `private readonly _ancestorIdsVersion: number[] = [];` parallel array.
- `intern()` (`:41-51`): delete the `this._ancestorIds.length = 0;` line
  entirely — no clear on new-path insertion.
- `ancestorIds(id)` (`:100-111`): change the cache check from
  `if (cached !== undefined) return cached;` to
  `if (cached !== undefined && this._ancestorIdsVersion[id] === this._paths.length) return cached;`.
  After computing `result`, store both
  `this._ancestorIds[id] = result; this._ancestorIdsVersion[id] = this._paths.length;`.
  This is exactly the report's recommended fix: a cached entry is only
  recomputed when it is actually re-queried AND the interner has grown since
  it was cached — correctness is identical to the coarse clear (a stale
  entry can never be returned) but the cost moves from O(all cached entries)
  per intern to O(1) amortized per read.
- **Dev-mode size-threshold warn** (same file, `intern()`): after the push,
  dev-only (`process.env.NODE_ENV !== 'production'`), warn once per interner
  instance when `this._paths.length` crosses a threshold (`5000`, matching
  the class-level `size` doc's "unbounded dynamic keys" framing at `:158-165`):
  `if (this._paths.length === 5000 && !this._warnedSize) { this._warnedSize = true; console.warn(...) }`.
  Add `private _warnedSize = false;`.

## 3. `deepMerge` lazy-clone
**File**: `packages/dirtytalk-structural/src/container.ts:453-479`
Execute `plans/patch-emit-redundant-diff-clone.md` Option B as written, with
the `setMergedKey` guard (added since that plan was written) carried
forward exactly as its own forward-comment (`:433-435`) instructs: replace
the eager `const out = {...target}` + unconditional per-key `setMergedKey`

## 4. `watch()` — per-instance dispose hook (kills O(watchers × app-disposals))
**Files**: `packages/blac-core/src/core/symbols.ts`,
`packages/blac-core/src/core/StateContainer.ts`, `packages/blac-core/src/index.ts`,
`packages/blac-core/src/watch/watch.ts`
- Add `export const ON_DISPOSE = Symbol('blac.onDispose');` to `symbols.ts`,
  same pattern as `APPLY_DEPS`/`REMOVE_DEPS_OWNER`.
- `StateContainer.ts`: add `[ON_DISPOSE](handler: () => void): () => void { return this.onSystemEvent('dispose', handler); }`
  near the other symbol-keyed methods (`:156`, `:192`) — delegates to the
  existing per-instance `_systemEventHandlers` 'dispose' channel that
  `dispose()` already fires via `emitSystemEvent('dispose', ...)` at `:434`,
  just exposing it past the `protected onSystemEvent`.
- `index.ts`: export `ON_DISPOSE` alongside `APPLY_DEPS`/`REMOVE_DEPS_OWNER`/`INIT_CONFIG`
  (`@internal`, same doc comment block, `:22-25`).
- `watch.ts` (`:225-286`): replace the per-target `registry.on('disposed', (container) => { if (container !== instances[index]) return; ... })`
  loop with a `subscribeDisposeAt(index)` helper that calls
  `instances[index][ON_DISPOSE](() => { channelUnsubs[index]?.(); channelUnsubs[index] = undefined; queueMicrotask(() => resubscribeAt(index)); })`
  and stores the returned unsub in `disposedUnsubs[index]`. Call it once per
  target in the initial setup loop, AND again inside `resubscribeAt` after
  `instances[index] = resolveBloc(...)` re-acquires (the new instance needs
  its own `ON_DISPOSE` subscription — the old one is stale/already-fired).
  `cleanup()`'s teardown loop (`for (const unsub of disposedUnsubs) unsub();`)
  is unchanged. Behavior is identical (fires only for that exact instance's
  own disposal) — this removes the global 'disposed' broadcast filter cost
  entirely; no more per-watcher check on every unrelated container's dispose.

## Risks & Mitigations
**Main Risk**: the DirtyChannel fast-path and `ON_DISPOSE` both touch
re-entrant/lifecycle-sensitive code paths; a subtle bug either double-fires
or silently drops a callback. **Mitigation**: fast-path reuses the exact
same per-entry `alive` check and never reads the live `#subscribers` Map
mid-loop, so re-entrancy semantics are structurally unchanged, only the
size<=1 snapshot allocation is removed; `ON_DISPOSE` is a pure
delegation to the already-tested `onSystemEvent('dispose', ...)` channel,
changing only who calls it and when.
