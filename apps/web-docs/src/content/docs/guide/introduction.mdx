**BlaC** (*Business Logic Components*) is a TypeScript state management library designed to keep your UI components thin, your business logic portable and easy to test, and your re-renders automatically scoped to the exact data each component reads.

A first taste — the whole loop in one screen:

```tsx twoslash
import React from 'react';
import { Cubit } from '@blac/core';
import { useBloc } from '@blac/react';

class CounterCubit extends Cubit<{ count: number }> {
  constructor() {
    super({ count: 0 });
  }
  increment = () => this.emit({ count: this.state.count + 1 });
}

function Counter() {
  const [state, counter] = useBloc(CounterCubit);
  return <button onClick={counter.increment}>Count: {state.count}</button>;
}
```

No store setup, no `<Provider>` wrapper, no reducer, no selector. The `Cubit` class holds the state and the logic that changes it; the component just renders `state` and wires `counter.increment` to `onClick`.

## Why BlaC?

Most apps start simple and gradually tangle three very different jobs inside the same React components: rendering markup, running business rules, and talking to APIs or storage.

BlaC is built around a clean separation of responsibilities (read the full story in [Architecture & Philosophy](/guide/philosophy/)):

1. **UI Layer (`@blac/react`, or any view library)**: Components take state, apply layout and styles, and fire callbacks when the user interacts with them. They never talk to APIs or databases directly.
2. **Logic Layer (`@blac/core` Cubits)**: Plain TypeScript classes hold your state, derived getters, validation, and coordination with external APIs. Because your core logic has zero dependency on React, you can test it in milliseconds with plain assertions—or reuse it in React Native, Vue, or a CLI tool without rewriting a line.
3. **Data Layer (APIs, IndexedDB, `localStorage`, memory)**: External data sources sit behind the Logic layer (or attach via [Plugins](/plugins/persistence/)), so you can swap local storage for a REST or GraphQL backend without touching your components.

On top of that architectural clarity, BlaC removes the day-to-day friction of React state management:

- **No providers or context wrappers.** Import your class, call `useBloc(MyClass)`, and you're connected. A reference-counted registry handles instance creation, sharing, and disposal automatically.
- **Re-renders are precise by default.** A render-time recording Proxy detects which leaf properties your component reads during render. Only changes to those exact paths trigger a re-render.
- **Lifecycle is declarative.** Instances are shared and auto-disposed when the last consumer unmounts by default. Use `args` for keyed instances, `@blac({ isolated: true })` for private per-mount instances, or `@blac({ keepAlive: true })` for persistent singletons.
- **Built for TypeScript.** State types, action methods, and `args` flow from your class definition through `useBloc` with zero manual type annotations.

## Package architecture

BlaC is split into focused packages that mirror the layered architecture:

```text
┌─────────────────────────────────────────────────────────────────┐
│  UI Binding      @blac/react          useBloc, BlocProvider,    │
│                                       RegistryProvider          │
├─────────────────────────────────────────────────────────────────┤
│  Logic Core      @blac/core           Cubit, Registry, watch,   │
│                  @blac/async          resource(), mutation(),   │
│                                       invalidate()              │
├─────────────────────────────────────────────────────────────────┤
│  Data & Tooling  @blac/plugin-persist IndexedDB & Web Storage   │
│                  @blac/devtools-*     In-app & Chrome DevTools  │
│                  @blac/logging-plugin Structured console logs   │
└─────────────────────────────────────────────────────────────────┘
```

- **`@blac/core`** provides `Cubit`, the reference-counted registry, cross-bloc composition (`this.depend()`), `watch()`, and the plugin system. It has zero React dependencies.
- **`@blac/react`** provides the `useBloc` hook, connecting components to the registry with per-consumer proxy tracking.
- **`@blac/async`** packages async data fetching (`resource`, `mutation`, and tag-based `invalidate`) directly into your Cubits' state slots.

<details>
<summary>Under the hood: the DirtyTalk engine family</summary>

The "what changed, who cares, when do we tell them" machinery — path-based dirty tracking, the render-time proxy, microtask-batched flushing — lives in a lower-level, framework-agnostic family of packages called [DirtyTalk](/dirtytalk/). BlaC's `StateContainer` extends `@dirtytalk/structural`'s container; you never need to touch it directly, but it's there if you want to understand the foundation.

## How does BlaC compare?

| Library | Where logic lives | How re-renders are scoped | Lifecycle & sharing |
| --- | --- | --- | --- |
| **BlaC** | Typed `Cubit` classes | Automatic render-time Proxy (zero selectors) | Ref-counted registry (shared, keyed, `isolated`, or `keepAlive`) |
| **Zustand** | Store creator function | Manual selector per hook (`useStore(s => s.x)`) | Module singleton (or manual context store) |
| **Redux Toolkit** | Slices, reducers, thunks | Manual `useSelector` + `createSelector` | Single global `<Provider store={...}>` |
| **MobX** | Observable classes | Observable proxies + `observer()` HOC wrapper | Manual instantiation / React Context |
| **Jotai** | Composed primitive atoms | Per-atom subscription | Provider / WeakMap per atom |

For a deeper side-by-side breakdown and guidance on when another tool is a better fit, see [Mental Model: Honest comparisons](/guide/mental-model/#honest-comparisons).

## When to use BlaC

BlaC shines when:

- You want **thin, declarative UI components** that only render state and fire interaction callbacks
- You have **meaningful business logic** (validation, multi-step flows, derived getters, cross-feature coordination) that belongs in a testable class rather than scattered across hooks
- Multiple components need to **share state** without prop drilling or provider pyramids
- You want **fast unit tests** that exercise your application logic without mounting React or mocking a browser

:::tip[When you probably don't need BlaC]
If a piece of ephemeral UI state lives in a single component and has no business rules behind it (like whether a tooltip is hovered), `useState` is the right tool. Reach for BlaC when state is *shared*, carries *business logic*, or is *worth testing outside the UI*.
:::
